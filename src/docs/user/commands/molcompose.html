MolCompose commands

MolCompose composes reproducible, publication-oriented protein structure figures. Every panel action in the MolCompose tool runs one of the commands below, so the ChimeraX Log always contains a complete, replayable recipe.

molcompose style

labels <n> overrides how many residues per side the preset labels, ranked by buried area; labels 0 turns them off. Without it each preset keeps its own count, and those counts differ by design — paratope-closeup labels two because two is what fits a tight close-up with its labels fanned apart, licorice-chain labels three, and the metric carriers label none. That is the right default for each preset alone and the wrong one for a multi-panel plate, where two panels then disagree about how many residues are named without anyone having chosen it.

Applies a versioned visual preset to the selected model. Presets are idempotent: applying the same preset twice produces the same state. The MVP presets are:

  • clean-cartoon — smooth single-color cartoon for monomers.
  • complex-by-chain — one stable, color-vision-conscious color per protein chain. Chain colors depend only on chain IDs, never on load order.
  • interface-focus — requires a completed molcompose interface analysis; shows interface residues as saturated sticks (Group A blue, Group B orange) over a subdued cartoon with a local semi-transparent surface, and fits the view to the interface.
  • design-reference — command-only comparison style. It aligns the named reference models on the target chain, displays their partner chains against the design, and maps the detected design epitope onto the target surface. Example: molcompose style design-reference model #1 references #2,#3 align A partner B.

Background, lighting, and silhouette settings are scene-global ChimeraX state; atomic representations and colors are scoped to the selected model.

molcompose interface

Detects interface residues between two protein chain groups. Chain groups are comma-separated chain IDs, for example A,B. The groups must not overlap. A residue pair is an interface contact when any heavy atom of one residue lies within the cutoff distance of any heavy atom of the other (inclusive). Hydrogens, waters, ions, and ligands are excluded. The cutoff defaults to 4.5 Å and accepts 2.0–10.0 Å.

The criterion option selects which atoms define a contact: heavy (default) uses every non-hydrogen atom; cbeta uses one point per residue — the Cβ atom, with Cα as the conventional glycine fallback. A typical Cβ cutoff is 8.0 Å.

Results (residue counts and contact-pair count) are reported in the Log and stored for the model, ready for interface-focus and molcompose focus.

molcompose interface all

Scans every protein chain pair of the model with the same rule and reports only pairs with at least one contact.

It is a survey and deliberately makes none of the pairs the active interface, because choosing one would silently replace an interface already set on purpose. Everything that measures or styles an interface — buriedarea, affinity, hotspots, contacts, hbonds, the interface presets — still needs molcompose interface <A> <B> naming the pair you want. The pairs found are remembered, so if you forget, the refusal lists them and suggests the one with the most contacts.

molcompose hbonds

Displays hydrogen bonds across the most recently detected interface using the native ChimeraX hbonds engine, restricted to contacts between Group A and Group B residues. off true removes them again. Run molcompose interface first.

molcompose contacts

Displays close-contact pseudobonds across the detected interface using the native ChimeraX contacts engine (VDW-overlap based), restricted to Group A ↔ Group B. off true removes them.

molcompose characterise

Runs the whole standard characterisation of one interface in a single call and returns one structured summary: interface residues and contacts, typed non-covalent interactions, buried surface area, predicted ΔG and Kd, the residues burying the most surface, prediction-confidence metrics where they apply, and the publication figure.

Steps that do not apply to the structure (confidence metrics on a crystal structure, for example) are reported as skipped with the reason rather than failing the call. Pass style false to compute without changing the display.

This exists because an agent choosing tools one at a time tends to stop early and miss most of the available analysis; the same is true of a hurried user.

molcompose report

Writes one file containing the complete characterization of the detected interface: geometry (chains, criterion, cutoff, residue counts, contact pairs, interface residue list), typed interactions, buried surface area, predicted ΔG/Kd, prediction-confidence metrics, an auto-written Methods paragraph, and the full command recipe that produced the numbers. Analyses that have not been run yet are computed automatically; those that do not apply (for example confidence metrics on an experimental structure) are omitted rather than failing the report.

The format follows the file suffix (.md, .json, .csv) unless format is given.

molcompose buriedarea

Buried solvent-accessible surface area (Å2) of the detected interface, via the native ChimeraX measure buriedarea.

molcompose hotspots

Ranks the interface residues by the surface area each one buries (per-residue ΔSASA = SASA of the residue in its isolated chain group minus its SASA in the complex). Residues burying less than minArea Å2 are omitted; top limits the list. This is the dependency-free hot-spot ranking; predicted ΔΔG from external tools can be layered on top.

molcompose ddg

Loads predicted mutation effects (ΔΔG) produced by an external predictor and ranks residues by them. MolCompose does not run the predictors: they carry dependencies (PyTorch/CUDA for Pythia and Pythia-PPI), proprietary licences (FoldX) or large installations (Rosetta). This command consumes their output, exactly as the predicted-structure workflow consumes AlphaFold files.

Two input formats are recognised:

  • tabular (.csv/.tsv): a header naming chain, position, wild-type, mutant and ΔΔG columns under any of several common spellings. FoldX, Rosetta and PythiaStudio exports can be reshaped into this form.
  • pythia (*_pred_mask.txt): Pythia's own output. Note: Pythia positions are sequential indices over the scored structure, not PDB residue numbers, so the open model must correspond to the file that was scored.

statistic selects the per-residue summary: min (most stabilising substitution, the default), max (most destabilising) or mean. Because different predictors are known to disagree substantially, each record keeps its source so several can be compared side by side.

molcompose affinity

Predicts the binding free energy (ΔG, kcal/mol) and dissociation constant (Kd, M) of the detected interface using the PRODIGY IC-NIS contacts model (Vangone & Bonvin, eLife 2015; Xue et al., Bioinformatics 2016). Requires molcompose interface first; the chain groups are taken from the detected interface.

The model is defined at a fixed 5.5 Å heavy-atom contact cutoff, so contacts are recomputed at that distance regardless of the cutoff used for the stored interface. The Log reports the four contact-class counts and the non-interacting-surface composition alongside the prediction.

Accuracy: the contact terms reproduce the reference implementation exactly. The %NIS terms depend on the solvent-accessibility engine — MolCompose uses native ChimeraX measure sasa, the reference uses freesasa — which shifts ΔG by 0.1–0.6 kcal/mol on benchmark complexes, well within the model's own reported RMSE of 1.89 kcal/mol. Predictions are validated for protein–protein complexes of standard amino acids.

molcompose interactions

Detects and displays typed non-covalent interactions across the most recently detected interface, following the conventions used by PLIP and Arpeggio. Requires molcompose interface first.

Each type is drawn as its own named, differently coloured pseudobond group; off true removes them. Every threshold is a command option, so the exact rule set is recorded in the Log with the result.

molcompose capabilities

Reports whether a structure is experimentally determined or predicted, and exactly which analyses it supports — with a reason for every metric that does not apply. Run this when a structure's provenance is unclear: it prevents asking for confidence metrics on a crystal structure, or for PAE-derived scores without a PAE matrix.

  • Experimental — geometry, buried area, ΔG/Kd, typed interactions and hot spots. No confidence metric applies.
  • Predicted (coordinates only) — the above plus pLDDT, ipLDDT and pDockQ.
  • Predicted with a PAE matrix — additionally ipSAE, pDockQ2 and LIS.

predictor (alphafold-server, alphafold-db, colabfold, boltz or generic) guides the search for a companion PAE file next to the structure; paeFile names one explicitly. DockQ is never listed as available because it needs a separate reference structure.

molcompose confidence

Reports prediction-confidence metrics computable from the structure file: the detected pLDDT scale, mean pLDDT, and — when an interface has been detected — ipLDDT (mean pLDDT over interface residues) and pDockQ (Bryant et al., Nat Commun 2022). The canonical pDockQ protocol uses criterion cbeta with an 8.0 Å cutoff. ipTM, pTM, and iPAE require the prediction's confidence JSON and are planned.

molcompose dockq

Scores a predicted complex against an open reference structure with DockQ (Basu & Wallner, PLoS ONE 2016; DockQ v2, Bioinformatics 2024) and its CAPRI components:

  • Fnat — fraction of reference interface residue contacts (5 Å heavy-atom) reproduced by the model, plus Fnonnat for novel ones.
  • iRMSD — backbone RMSD over reference interface residues (10 Å definition) after optimal superposition.
  • LRMSD — backbone RMSD of the smaller chain group after superposing the larger one.

DockQ combines the three as (Fnat + 1/(1+(iRMSD/1.5)2) + 1/(1+(LRMSD/8.5)2))/3 and is reported with its CAPRI band (High ≥ 0.80, Medium ≥ 0.49, Acceptable ≥ 0.23).

Chain groups come from the model's detected interface; use chainMap (for example A:C,B:D) when the reference uses different chain IDs. Residues are matched by chain, number and insertion code.

Note: unlike pLDDT, pDockQ and ipSAE, which score a prediction on its own, DockQ requires a trusted reference structure.

molcompose ipsae

Computes ipSAE interface scores (Dunbrack, bioRxiv 2025; d0res variant) for every chain pair from a prediction's PAE file — AF2/AF3/ColabFold JSON or Boltz NPZ. The PAE token count must equal the model's amino-acid residue count; models with ligands, nucleic acids, or modified residues are rejected with an explanation. Reports both asymmetric values and the pair maximum.

molcompose focus

Fits the view to the whole model (focus model) or to the most recently detected interface (focus interface, the default).

molcompose export

Exports a publication image using the native ChimeraX save command with explicit width, height, supersampling, and background transparency. Width and height accept 1–16384 pixels; supersample accepts 1–8. The output path must end in .png, .tif or .tiff — both lossless, which JPEG is not on a hard silhouette against a white ground. Existing files are never overwritten unless overwrite true is given.

dpi is written into the saved file's own metadata, so a publisher reads the figure's physical size rather than asking for it again; it accepts 72–2400, or 0 to leave the file unstamped. It does not change the pixels — 2008 px at 600 dpi is 85 mm wide, a single column.

keyFontSize sets the colour key's font, in pixels of this image, for this export only; the scene's own size is put back afterwards. The key's font is in pixels, so what it comes out as in print depends on how wide the image is placed: the default suits one panel across two columns and is too small for the same panel as one cell of four. Both key commands go into the recipe, so a replay reproduces the figure. Asking for it with no colour key in the scene is an error rather than a silent generic scale.

With saveSession true, a ChimeraX session (.cxs) is saved alongside the image. With saveRecipe true, the command recipe that produced the figure is written beside it as a .cxc command file, so the figure can be replayed on another machine and after this session closes.

What a ΔΔG file has to look like

molcompose ddg does not run a predictor and does not know one predictor's output from another's. It reads three shapes, and picks between them by the file's name and header unless format says otherwise:

  • tabular — any CSV or TSV with a header row. It needs columns for the position (position, pos, resnum, residue, resi or res_num), the mutant residue (mut, mutant, to or alt) and the value (ddg, delta_delta_g, score, energy or prediction). A chain (chain, chain_id, chainid) and a wild type (wt, wild_type, from, ref) are optional but worth giving: the wild-type letters are what verify the file describes this structure, and without a chain the values cannot be placed on a complex. Rows that do not parse are skipped rather than failing the file.
  • pythia — Pythia's own mask output, recognised by pred_mask in the filename. Its positions are sequential indices, not residue numbers, and are mapped back through the structure.
  • pythia-ppi — PythiaStudio's binding-ΔΔG export: an .xlsx workbook, or a CSV whose header is exactly Mutation,Chain,Position,ddG.

Other predictors need a conversion first. FoldX, Rosetta and most web servers write their own layouts — FoldX's .fxout files, for instance, carry the mutation in a separate list and the energy under total energy, which none of the readers above accept. Reshaping such output into the tabular form is a few lines of a script and is deliberately left outside this tool: MolCompose reads predictions, it does not pretend to know every predictor. The button says Load ΔΔG because the quantity is what matters to the figure; the format is this section's business.

molcompose flexibility

Loads per-residue RMS fluctuation written by gmx rmsf -res — the one thing every other metric here is blind to, since all of them describe a single conformation and this describes how much that conformation moves. Values are converted from nm to Å on the way in.

chains names one chain per block of the file, in the order the selection was written, as in chains A,D. It is required because gmx rmsf -res restarts its numbering at each chain: a two-chain file reads 1–110 then 1–89, not 1–199, and nothing in it says which chain is which. Read as one running index, the second chain's fluctuations land on the first chain's opening residues. Each block's length is checked against its chain, and a file that does not line up is refused rather than trimmed.

Fluctuation is not a contribution. A residue that moves a great deal may be a flexible loop nowhere near the interface, and one that barely moves may simply be buried in the core, so color by rmsf uses a sequential ramp — more is more — rather than the diverging one the energies get.

molcompose energy

Loads the per-residue MM/PBSA decomposition gmx_MMPBSA writes (FINAL_DECOMP_MMPBSA.dat) and attaches it to a structure, giving a third answer to which residue matters: buried area is geometry, predicted ΔΔG is what removing a residue costs, and this is what keeping it earns. Only the file's DELTAS section is read — the complex, receptor and ligand sections are absolute energies of one state, an order of magnitude larger and a different quantity.

chains maps the file's chain letters onto the model's, as in chains A:A,B:D, and is required rather than inferred. GROMACS relabels chains when a system is built, so a decomposition of PDB 1BRS arrives with chains A and B where the structure has A and D. The file's residue names are then checked against the structure, and a map the structure contradicts is refused: attaching one partner's energies to the other is the same class of error as scoring DockQ against a differently numbered reference.

solvation is gb or pb, and is required only when the run computed both. gmx_MMPBSA then writes the whole decomposition twice, once under each heading, and the two disagree by several kcal/mol — on the packaged 1BRS run the overall figure is −80.75 under Generalized Born and −72.93 under Poisson Boltzmann. A file carrying both is not one result to be averaged, so the command names the choice rather than making it. The three packaged examples all carry both.

The values keep the file's sign — negative where a residue contributes favourably — which is the opposite of the ΔΔG convention. See color by mmpbsa for what that means for the colour scale. The absolute binding energy is not read: MM/PBSA totals are not comparable with the predicted ΔG this tool reports, so only the per-residue decomposition is loaded.

molcompose color by

Paints residues by a per-residue value instead of by chain: plddt and bfactor are read from the structure, ddg from a loaded mutation scan, and dsasa is the buried area each residue contributes. A colour key is drawn from the same scale the residues were painted with, because a key assembled separately is a promise to eventually disagree with the figure.

mmpbsa needs molcompose energy first. It is drawn on the diverging ramp read the other way round, so that the end meaning “matters more” is the same colour as it is for ΔΔG — the two are both kcal/mol and mean opposite things by the same sign, and one ramp would make red mean “important” on one panel and “unfavourable” on the next. The numbers are not flipped: the key shows the file's own values, signs included.

statistic chooses how a residue's several values become one — max by default, which is the disruptive substitution for a ΔΔG scan. scope defaults to interface, which is what these metrics are about; scope all paints the whole structure, and is refused for dsasa, which is only defined by what two chains bury between them.

molcompose hotspots

metric dsasa, the default, ranks interface residues by buried surface area. metric energy ranks them by MM/PBSA contribution to binding, most favourable first, and needs molcompose energy loaded. They are different questions and can disagree — on barnase–barstar Asp35 buries the second-most surface of any residue and does not reach the top ten by energy — so the log says which one it answered.

molcompose blocks

Lists the four named parts a characterised complex is divided into — the group A and group B chains, and the interface residues on each side. Each is a real ChimeraX name, so it can be selected, recoloured, and referred to in any native command.

molcompose source

Declares who issues the next recorded command, for the recipe's source attribution. It exists because ChimeraX's remote control cannot tell an agent from a script from the user's own curl: a caller that knows who it is has to say so. One-shot on purpose — it applies to the next recorded command and then reverts, so a bridge cannot leave a flag set that attributes the user's later typing to an agent.

molcompose seqcolor

Writes the per-residue colouring as an SCF (Sequence Coloring Format) file and, unless load false is given, opens the chain's sequence and loads it — so the quantity that colours the structure can be read along the sequence, where the extent of an interface or a low-confidence stretch is a shape rather than a scatter of highlighted residues.

source selects what is drawn: interface (the detected interface, in the interface preset's own two colours), plddt (the four AlphaFold confidence bands), ddg, dsasa or bfactor (the same diverging and sequential ramps the structure gets). The colours come from the same functions that paint the structure, so the two views cannot disagree.

One file is written per chain — SCF positions are alignment columns of a single sequence — and a multi-chain export appends the chain id to the filename. Those positions are not residue numbers: they count from the start of the chain's sequence, including any residues the structure does not resolve. Omit the path and the file is written beside the structure, or in the temporary directory when the structure has no file of its own.

Regions in the Sequence Viewer are named after what they show ("interface, group A", "pLDDT 70-90"), so the region browser lists bands rather than hundreds of single columns.

molcompose reset

Restores the documented MolCompose neutral baseline (cartoon-only, neutral color). It does not attempt to reconstruct arbitrary prior appearance state; preserve complex prior state with a native ChimeraX session.

Model selection

When model is omitted and exactly one protein model is open, that model is used. With zero or multiple protein models open, the command reports the available model IDs and asks for an explicit choice.

Errors

Invalid input (unknown preset, overlapping or unknown chains, cutoff out of range, invalid dimensions, existing output file) produces a readable error message instead of a Python traceback, and never modifies molecular data.
